# Custom changes to graphify

This is nCoder's copy of graphify. Keep every change to upstream code listed here, so the copy can be re-based later.

**Upstream base:** PyPI `graphifyy` 0.9.108 (the wheel, unpacked and diffed on 2026-11-20).
**Copy source:** `feat/react-source-support`, `third_party/graphify`, last graphify commit `e5581269`.

## Summary

Compared with the 0.9.108 wheel, the package has:

- 5 upstream files changed: `rcfile.py`, `extract.py`, `extractors/engine.py`, `export.py`, `llm.py`.
- 4 modules that the wheel doesn't have: `gateway.py`, `descriptions.py`, `descriptions_llm.py`, `ts_relations.py`.
- Not code: `extractors/MIGRATION.md` is upstream documentation that the wheel leaves out.

`pg_introspect.py` is identical to upstream. Its f-strings are upstream code, which the repo's SQL-safety test flags (see the test notes in the service repo).

## Changed upstream files

### 1. `rcfile.py`: per-run language overrides (custom extraction)

- New environment variable `GRAPHIFY_LANGUAGE_OVERRIDES`, for example `tpl=ts,inc=php`. Each pair maps a file extension to a language, using the same value rules as `language.<ext>=` in `.graphifyrc`.
- It is merged over the repo's own `.graphifyrc`, and wins on a clash. An unset or empty variable changes nothing.
- A bad variable is reported once on stderr and ignored, the same way a bad `.graphifyrc` is handled.
- New: `parse_env_overrides(raw)` and `ENV_LANGUAGE_OVERRIDES`. `activate_language_overrides` reads the variable.
- **Why:** a repo's `.graphifyrc` lives in the checkout, which the runner keeps unmodified. An environment variable also reaches graphify's worker processes.
- **Behaviour that follows:** the AST cache key includes the active mapping (`cache_salt`), so a changed mapping never reuses a stale parse.
- **Limits:** only languages in `LANGUAGE_ALIASES` or extensions graphify already knows. It adds no new extractor.
- **Tests:** `tests/test_graphify_language_overrides.py` in the service repo (10 tests).

### 2. `extract.py`: line spans and the TypeScript post-pass

- New `_fill_line_spans(nodes, root)`: every node gets `start_line` and `end_line`. A node that already has a span keeps it. A file node spans its whole file. A node with no location gets `None`.
- A post-pass calls `ts_relations.add_ts_relations` before the graph is built, but only when `GRAPHIFY_TS_RELATIONS` is on. Errors in the pass are printed and never stop extraction.

### 3. `extractors/engine.py`: definition end lines

- Functions, classes, properties and methods across the languages pass their end line to `add_node` (new keyword `end_line`). Those nodes get `start_line` and `end_line`.
- Affected: nested functions, class declarations, C# properties, Swift computed properties, C/C++ member and function definitions, Ruby class declarations.

### 4. `export.py`: missing line fields

- Every node gets `start_line` and `end_line` set to `None` if it has neither (external references added during a build).

### 5. `llm.py`: gateway backend

- The backend name `gateway` is dispatched to `gateway.call_gateway`. Every other backend works as before.

## New modules (not in upstream 0.9.108)

### `gateway.py` (75 lines): the LLM gateway

- LLM calls through the nCoder gateway (LiteLLM), selected with `GRAPHIFY_BACKEND=gateway`.
- `LLM_SIMULATION=true`: no network, canned replies in the shape the description steps expect.
- Unset: a real call to `LITELLM_BASE_URL` with `LITELLM_API_KEY`. Every real call needs `GRAPHIFY_CUSTOMER_ID`. `GRAPHIFY_MODEL` names the model.

### `descriptions.py` (165 lines): descriptions in `graph.json`

- Adds a top-level `communities` list (`id`, `name`, `description`, `size`, `members`) and a `description` on every node.
- `GRAPHIFY_DESCRIPTIONS` unset: deterministic template text from the structure, no LLM. `llm`: generated by the LLM backend.
- Community names are graphify's own and are never changed here.
- CLI: `python -m graphify.descriptions apply <graph.json>`.

### `descriptions_llm.py` (302 lines): LLM descriptions

- Sends node source ranges and community member names in batches, in parallel (`GRAPHIFY_DESCRIPTION_WORKERS`, default 8; `GRAPHIFY_DESCRIPTION_BATCH`, default 15).
- Caches results in `<graphify-out>/descriptions_cache.json` after each batch. A rebuild only asks for nodes whose code changed.
- `GRAPHIFY_DESCRIPTIONS_DRY_RUN=1` counts requests and tokens without sending anything.

### `ts_relations.py` (846 lines): React/TypeScript relations

- A post-pass over TS, TSX and JSX files, derived from the AST and imports.
- Adds `renders`, `calls_hook`, `uses_store`, `route_renders`, `tested_by` and `uses_gql_operation` edges, and a `type_only` flag on JS/TS import edges.
- **Off by default.** Enabled only with `GRAPHIFY_TS_RELATIONS=1`. The React graph built on 2026-11-20 has none of these relations, so the flag was off for that run.
- **Known issue (found 2026-11-20 with a sample React repo):** an added relation replaces any existing edge between the same two nodes instead of sitting beside it. On the sample, 12 existing edges were replaced (9 `calls`, 1 `contains`, 1 `imports`, 1 `imports_from`) and 13 relation edges were added. The pass also logs more edges than the graph keeps. The fix belongs in the dedup step: the key should include the relation.

## Known issues

- **`requests` is not declared.** `gateway.py` imports `requests` inside `call_gateway`. The package does not list it, so real gateway calls fail on a fresh install with `ModuleNotFoundError`. Fix: declare it in `pyproject.toml`, or use `urllib`.
- **Configuration and import errors are retried.** `descriptions_llm.py` retries every exception six times with waits (about six minutes in total). A missing module or a missing gateway setting should fail at once.

## Not code

- `extractors/MIGRATION.md`: the upstream playbook for moving language extractors out of `extract.py`. Upstream includes it in the repository but not in the wheel.

## Service side

- `run_graphify` in `app/services/react_source/graphify_runner.py` builds the environment with `dict(os.environ)`. Setting `GRAPHIFY_LANGUAGE_OVERRIDES` or `GRAPHIFY_TS_RELATIONS` there passes it through. That file lives on `feat/react-source-support`.
